## 学习方法

1. **先预测，再运行。** 数组先写 shape、axis 和预期结果；表格操作先判断行数、键和统计含义。用能手算的小样本核对。
2. **每天一个主要问题。** 阅读当日所需小节后自己实现，已会的内容通过变式确认后跳过。数学课与编程练习共用一个问题，不分成并行作业。
3. **工程习惯随题加入。** 输入输出约定、避免副作用、边界检查、依赖/种子/参数记录和独立重跑逐步增加，不先搭复杂框架。
4. **同一批实验结果反复使用。** NumPy 产生计算结果，pandas 整理实验表，Matplotlib 展示误差或收敛现象，最后形成可重跑流程。
5. **材料与掌握分开。** 助手写的说明、示例与检查只是教学材料；自己的代码、实际输出和解释才是验收依据。
6. **记录错误如何解决。** 经验包含问题、原因、修改、验证和适用范围，避免只抄 API。

## 数值主题怎样嵌入，而不是额外加课

| 编程能力 | 数值线性代数题材 | 数值分析题材 |
|---|---|---|
| 数组、索引、广播 | 列视角、向量/矩阵范数、投影 | 采样网格、多项式求值、插值 |
| 函数、循环与矩阵运算 | 回代、消元/选主元、Gram–Schmidt、QR | 二分/牛顿迭代、梯形/Simpson、Euler/RK |
| 误差、参数扫描与验证 | 条件数、残差与解误差、SVD 低秩近似 | 舍入/截断误差、步长选择、收敛阶 |
| pandas、Matplotlib、重跑 | 对照不同矩阵/算法/精度 | 对照不同节点/步长/算法 |

表中为可选题材池，并非已经布置或完成的全部任务。按课程实际进度与编程缺口选择，任何时候只保留一个待完成核心练习。学习算法时自己写小规模核心步骤，再与参考实现及手算核对；使用算法时可调用库，但不能把一次库调用当作算法实现能力。

## 贯穿产物：自己的数值实验记录分析器

优先使用本人实际运行的小规模数学实验结果，建议从 5—20 条开始，再扩展到 20—100 条。

| 数据表 | 起步字段 | 用到时才增加的字段 |
|---|---|---|
| runs | run_id、problem、method、dtype | n、h、seed、参数说明 |
| metrics | run_id、metric、value | step、seconds、reference_source、status |

误差、残差与参考值必须说明定义，单位不能混用。不适用的字段留空并说明；没有计算参考解时不伪造误差。初期可用明确标注“教学模拟”的极小表测试清洗，但不能据此评价算法。将来训练日志沿用同一分析流程，训练字段仅在需要时加入，不同时维护两套贯穿项目。

流程：生成计算结果 → 读取 → 检查 → 清洗 → 合并 → 汇总 → 绘图 → 保存。原始数据只读。最终保留汇总 CSV、2—3 张有解释的图、可重跑入口、必要依赖、少量关键测试和 README。

**真实 AI4 水处理数据暂不引入。** 未来取得授权后先查字段、单位、时间戳、采样频率、缺失异常与数据泄漏，再在 numerical-computing-lab 建立真实数据基线。当前不上传公司原始资料、不预设已有现场数据或硬件接入。
