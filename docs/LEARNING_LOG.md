## 记录原则

- “材料已准备”“本人已提交”“程序已验证”“理解已验收”分别记录，不混用。
- 有代码不等于执行过；有正确输出不等于能解释；助手跑通不等于本人掌握。
- 结论要能指向代码、输入、实际输出或本人说明。未验证写“待验证”，不补造实验结果。
- 同一任务继续追加进展，不每天复制一份。若没有新证据，保留原状态。
- 失败也值得记录：当时现象、原因判断、修改、复测和结论边界。
- 不记录凭据、密钥或含个人隐私的原始数据。

## 2026-10-29｜PY01-list-summary｜嵌套字典、遍历与空列表修复

**状态：**用户练习代码已归档；助手修复后程序已验证；用户对本次修复的理解待确认。

**代码与环境：**[现有练习](../grammar/10_27/10_27_test.py)，MacBook，Python 3.14.4。数据是虚构教学分数。命令从仓库根目录运行：

```bash
python3 grammar/10_27/10_27_test.py
```

**用户练习：**在逐步讲解后，用户修改了阈值参数和严格大于筛选，使用嵌套字典保存多组输入，并加入外层遍历与格式化打印。用户主动将最后一组从 `[0]` 改为 `[]`，报告运行错误并要求检查后提交。用户正确回答列表 `[100, 8, 60]` 的长度为 3；这些证据不等于已独立掌握全部函数与边界处理。

**问题与复现：**助手运行用户当时保存的版本，前三组打印成功，第四组在 `sum(scores) / len(scores)` 报 `ZeroDivisionError`。空列表的长度为 0；`[0]` 则包含一个零分，两者含义不同。

**助手修改：**

- 先计算人数，空输入返回 `mean=None`，有数据时才做除法。
- 返回字段与任务约定对齐为 `count / mean / above / above_count`，用 `len(above)` 复用筛选结果。
- 输出时单独处理 `None`，显示“无数据”；数值才按 `:.2f` 保留两位小数。
- 保留用户的数据字典、单个统计函数与遍历打印结构，整理缩进与空格。

**实际结果：**以下为助手修复后运行并用断言核对的结果，不记为用户独立运行或理解已验收。

| 案例 | 输入 | 阈值 | count | mean | above | above_count |
|---|---|---|---|---|---|---|
| scores1 | [60, 80, 80, 100] | 80 | 4 | 80.0 | [100] | 1 |
| scores2 | [60, 80, 80] | 80 | 3 | 73.33333333333333 | [] | 0 |
| scores3 | [80] | 80 | 1 | 80.0 | [] | 0 |
| scores4 | [] | 80 | 0 | None | [] | 0 |

四组调用前后的输入列表均相等，返回筛选列表为新列表；返回键与值一致通过。程序完整打印四组，第二组平均分显示为 `73.33`，第四组显示“平均分：无数据”，没有异常。

**可复用经验：**先定义空输入的返回约定，再计算；格式化输出也要遵守这个约定。遍历外层字典每次取一个案例，把统计计算集中在函数中。

**下一步：**用户用自己的话解释严格 `>`、空列表返回 `None` 以及 `return` 与 `print` 的分工，再确认理解验收。代码通过后不追加第二个核心练习；不将助手修复记为用户独立完成。
